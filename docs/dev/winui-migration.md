# WinUI 迁移现状

本文从 AGENTS.md 拆出，记录 `src/MyDesktop.WinUI` 已迁移的功能、实现要点、实测约束和尚未迁移的部分。改 WinUI 入口的代码前阅读。

- WinUI 已接入真实分区及标签组、Shell 图像、映射目录、物理像素位置保存、四向收起、桌面层级维护、分区标题及普通文件改名。分区与散放图标共用 `NameEditor`，散放图标可通过右键菜单或 F2 改名；结束后恢复非激活状态，系统入口改名尚未迁移。文件名检查、扩展名保留及路径引用同步在共享核心中，实际改名复用 Shell 文件操作。输入法组词期间不提交改名，但候选窗与真实输入体验仍需实机验收。
- WinUI 已接入散放图标基础接管：桌面快照和 COM 读取器与旧入口共用，独立 STA 线程每 3 秒读取一次；散放图标画在每屏现有宿主内，排除全部桌面标签成员，自动排列时避开分区，自由排列时沿用 Explorer 坐标。分区与散放图像就绪、键盘保护及恢复进程均就绪后才隐藏系统列表。
- 恢复进程以 `--guard` 进入，不创建 XAML 界面，绑定明确的桌面根窗口、图标列表及所属进程，不重新寻找其他桌面。正常退出、读取失败、恢复保护失效时恢复系统图标；主进程被强制结束时由恢复进程恢复。恢复时即使列表当前仍可见也要提交显示请求，覆盖尚未执行的异步隐藏请求。用户主动关闭「显示桌面图标」时不强行显示，Explorer 窗口重建后重新读取与接管。
- 分区和散放图标共用 `ItemSelection`，支持单选、跨区域追加选择、打开、改名、全选、键盘导航和普通文件的复制、剪切、粘贴、删除；切换标签或收起分区清理隐藏内容的选择，刷新保留仍存在项目的选择及剪切淡化状态。
- `FileCommands` 使用原生 CF_HDROP / Preferred DropEffect 与 Shell 互通，按序号清除本次完成的剪切，不能清掉操作期间的新剪贴板。
  桌面内剪切只变更成员，复制或跨目录移动使用独立 STA 上的 `IFileOperation`，按逐项回调的实际路径同步归属；重名不猜文件名，部分失败不清剪切列表。
  同卷移动成功可返回 `COPYENGINE_S_DONT_PROCESS_CHILDREN`，不能只认 S_OK。
- Delete 使用回收站及永久删除警告，Shift+Delete 尚未迁移。系统入口不按普通文件复制或删除；完整系统菜单和系统新建后的改名接手仍需后续迁移。
  未实现操作会被截住并明确提示；Win 快捷键、其他程序及系统菜单输入照常放行，吞掉的按下和松开成对处理。
- 左键框选已连接分区和散放图标：按开始时的选择重算，Ctrl/Shift 追加，取消恢复；选框画在已有宿主内，桌面框选越过阈值后才临时扩展输入区域。
  空闲时鼠标移动直接放行，仅框选期间合并投递最新位置；所有鼠标按下、松开均放行，Escape、Win 键、Alt+Tab、右键及接管撤销会取消框选。
- 普通文件和文件夹拖放使用 WinUI 的数据包，分区使用 GridView 列表拖动事件，StorageItems 按需异步提供，支持跨区域多选。
  分区或桌面空白作为放置目标；桌面内部只改归属，跨目录复用逐项确认的 Shell 文件操作，同盘默认移动、跨盘默认复制，Ctrl 复制、Shift 移动。
  移动由目标完成后回报 None，源端不再删除；拖放不读写剪贴板。图标自身的 Shell 放置目标、系统入口拖放、快捷方式创建及分区内排序尚未迁移，禁止误当成空白放置。
- 内部拖动期间临时扩展每屏宿主的放置范围，结束或取消恢复穿透；框选、拖动期间暂缓内容替换，结束后只补读期间被暂缓的分区与文件变化（`DesktopSession.InteractionFinished`），避免移除正在拖动的控件；不能结束后整体重读，否则每个分区的图标列表都会清空重建，拖动或点击标题栏后分区闪一下（实机反馈）。
  拖回桌面在独立 STA 上写回 Explorer 位置，散放拖动保留相对位移，分区拖出从落点依次排开；自由排列按目标显示器缩放换算图像偏移，自动排列交给 Explorer 排序。
  隔离检查只更新测试快照，不写真实桌面。系统拖放循环、外部应用互通及实际手感仍需人工验收。
- 隔离文件命令验证用内存剪贴板，只操作测试目录，不写用户回收站或 Shell 撤销历史；原生剪贴板仅在新建私有窗口站的辅助进程中验证。普通权限无法创建时报告「未执行」，不得改在共享剪贴板上测试；与 Explorer 的实机互通及正式回收站对话框仍需人工验收。
- WinUI 的 `FileChangeMonitor` 监视桌面与映射目录，变化后在 300、1200 毫秒补读；外部改名同步全部标签成员、自定义顺序、映射路径和使用记录，目录改名连同后代引用更新。快捷方式由 `.lnk` 临时改为备份扩展名时保留原成员。嵌套映射由祖先目录的一份递归监视覆盖，避免子目录监视句柄阻止父目录改名；额外监视映射根目录的父目录以接收根目录改名。仅合并嵌套配置，不对所有目录默认递归监视。
- 文件监视刷新保留正在输入的改名草稿，结束编辑后补读；分区内容加载完成后统一替换，等待内容时会跟随被后续刷新取代的任务。
  散放刷新用版本记录期间新增的成员变化，不能由旧任务清掉新的刷新请求。文件通知先于 Explorer 快照时暂留当前散放视图，不用失效旧路径重画，持续不同步时恢复系统图标。
  桌面目录未被监视时拒绝接管，监视报错时恢复系统图标并明确提示重启，不能仅刷新后继续隐藏系统列表。
- WinUI 已接入分区边框与角点调整大小、屏幕与邻区吸附、整行整列尺寸吸附及重叠避让；几何规则位于共享核心 `FenceGeometry`，按起点绝对位移和宿主缩放计算。
  调整大小止于邻区；移动松手后滑到最近空位，放不下回到起点。收起时只沿标题条长边调整，保留展开高度；位置和尺寸同步组内标签。
  布局操作期间暂缓内容替换，取消或接管撤销时恢复原布局；点击和拖动只调整宿主内分区顺序，不提升整个宿主。
- WinUI 已接入同屏标签组合并、排序与拆分：普通拖动到另一分区的标题栏合并整个来源组，沿用目标布局并显示来源当前标签；Shift 拖标签在条内排序，拖出标题栏显示拆分预览，松手后避让邻区。
  菜单支持标签左移、右移和拆出；鼠标悬停切换遵循既有开关与延迟，滚轮到头不循环。锁定分区仍可切换标签，但不能合并、排序或拆出。
  合并复用目标视图，拆分只在原宿主中增加分区视图，不重建宿主或接管服务；切换时立即清除旧内容，合并和拆分保留仍可见项目的选择。
  标签拖动、取消及接管撤销共用交互状态，预览和输入区域在结束后释放；文件拖动期间暂不切换标签，跨标签悬停放置随文件拖放细节继续迁移。
- `SystemAcrylicBackdrop` 仅供分区的 `SystemBackdropElement` 使用：断开时移除控制器目标，并在界面线程显式关闭外部背景链接。
  等待 .NET 终结线程释放会在 `ContentExternalBackdropLink::Dispose` 关闭 `ContentSite` 时触发原生 fail-fast；隔离检查通过移除视图后的主动回收复现此问题。
  相同材质复用原 `SystemBackdrop` 对象，不能非空替换后重用已关闭的链接；该类型不能用于窗口或弹出窗口的背景，否则会关闭不属于它的目标。
- 四向收起使用 `FenceRoll` 计算标题锚点、内容区与收起条；配置始终保存展开范围，分区避让和散放图标布局只计算收起条。自动方向优先上下屏幕边缘，移动收起条换边后反推展开范围，标题留在松手位置。
  `FenceView.Roll` 使用 Composition 的几何裁剪动画，内容按展开尺寸排列；界面线程只按动画进度更新输入区域，不逐帧改窗口或内容尺寸。动画可以中断和反向，标题栏随收起方向旋转。
  悬停遵循 `ExpandOnHover` 和 `CollapseDelay`；拖入文件可以展开收起的分区，拖放、菜单或编辑进行中延后收回。临时状态只保存在视图中，不改写 `RolledUp`。
- 收起的分区常驻 `ExpandedSurface`（同屏收起分区共用的浮层，按需创建），固定展开的分区及散放图标留在桌面宿主；只在收起、固定展开切换时迁移视图。
  浮层平时与桌面宿主一样紧贴桌面、位于主宿主上方；悬停或拖放临时展开时整体提到普通应用上方、任务栏和其他置顶窗口下方（同屏其他收起条随之提升），收回动画结束后放回桌面层。
  不能改回展开时把视图迁到另一个窗口：迁移那一下源窗口已移除、目标窗口还没画出，分区会整块闪一下（实机反馈，移入移出各闪一次）。
  主宿主与浮层都插在同一参照之下，后移动的排在上面，浮层在主宿主下方时也要重新插入（`DesktopPlacement.AnchorAbove`）。
  浮层只归属于同进程的桌面宿主，不能与 Explorer 建立 owner/parent 关系。接管撤销时浮层立即回到桌面层，不取消普通桌面分区的编辑。
  分区内框选和标签拆分预览随来源视图选择绘制宿主，浮层预览同步扩展局部输入区域，结束或取消时清理。
  Win+D 把主宿主临时提到置顶层时，浮层的排序参照不能越过主宿主，否则会选到它后面的系统输入指示器，导致浮层压到主宿主下方；撤销全体提升后，恢复浮层在置顶层底部的次序。
- 尚未迁移的功能清单维护在 `docs/TODO.md`；完成前不能作为现有完整功能的替代发行版。旧毛玻璃枚举暂映射为系统亚克力。
  当前优先完成功能迁移，内存问题在迁移完成后再集中评估；拖动延迟也保留为后续优化。
- WinUI 层级检查覆盖编辑前、首次输入后及文件改名后。首次激活会生成归属于宿主的隐藏 IME 窗口；桌面已在最前且没有安全参照时，`HWND_TOP` 会被解析为该 IME 窗口，宿主及其名下窗口会掉到底层。此时直接以 `HWND_TOPMOST` 临时提起，普通应用回到桌面上方后随参照撤销置顶。不要改动输入法窗口的 owner，也不要把桌面设为 owner。
- 分区材质用 `SystemBackdropElement` 加 `DesktopAcrylicController`，配置 `IsInputActive=true`：桌面宿主几乎总是未激活，不设的话材质退回纯色。
- 宿主的透明底面依赖 DWM 配置（`DwmExtendFrameIntoClientArea`、`DwmEnableBlurBehindWindow`）、`WM_ERASEBKGND` 原生清除和非客户区处理（`TransparentBackdrop`），改动这些曾造成黑边、拖动时分区以外黑屏。
  也不要为了接收输入无条件把窗口区域扩成整屏，空白处必须继续穿透。
- 不要在通用的 `CancelInteractions` 里无条件收回临时展开：右键按下也会经过它，会破坏菜单。
- `App.xaml.cs` 的未处理异常回调只记日志、不标记已处理，界面线程异常会直接结束进程（拖动崩溃实证），恢复进程负责还原系统图标。
- 隔离 UI 验证直接调用布局入口并检查合成状态，不能代替真实 `PointerMoved`、系统拖放循环和可见画面；闪烁、跟手这类问题要实机验收。
- `artifacts/architecture-prototypes` 是选型阶段的原型，只作历史参考，不随 Git 交付，其中结论可能早于正式迁移。
